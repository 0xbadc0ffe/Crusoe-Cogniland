Cogniland A minimal POMDP where the only difficulty is remembering — and three agents that solve it: recurrent PPO, DreamerV3, and STORM

Environment Cogniland (bridge_tunnel engine) Agents PPO+GRU · DreamerV3 (RSSM) · STORM (Transformer) Data forkwall6k, 4 800 train / 1 200 held-out maps Evaluation 900 held-out episodes per agent, identical harness
Abstract

Cogniland is a 32×64 grid-world POMDP built so that memory is the only hard part. Terrain statistics at the start of an episode identify one of three map categories; the category is then hidden behind an information-free corridor; at the far wall the agent picks one of two doors, and only the door matching the remembered category pays. Navigation is easy, the reward is dense, and a memoryless policy is capped at ⅔ success. We train three agents — recurrent PPO, DreamerV3 with an RSSM world model, and STORM with a Transformer world model — on a byte-identical environment, reward and fixed map dataset, and evaluate all three through one harness on 900 held-out episodes. All three clear the memoryless ceiling and land within 0.7 percentage points of each other: 98.6 % (PPO), 98.1 % (Dreamer), 98.8 % (STORM); no pairwise difference is significant (p > 0.25). What separates them is not final score but what each needed in order to escape the constant-door optimum: PPO needed an annealed high-entropy schedule, and both world-model agents needed a training window at least as long as the ~75-step evidence→door dependency. We report the full sweeps, the training telemetry, and a metric pitfall that inflates success by 6–13 points if unnoticed.

1Why this task exists

Most benchmarks that require memory also require something else — exploration, credit assignment over sparse reward, visual abstraction, long-horizon control. When an agent fails, the failure is hard to attribute. Cogniland was built to remove every confound except one.

The design constraints were: (i) the information the agent must retain is a single categorical variable, visible early and never again; (ii) the delay between seeing it and needing it is long enough to defeat a short context window, but short enough that episodes stay cheap (~95 steps for a good policy); (iii) navigation is dense-rewarded and easy, so a failure is a memory failure, not a control failure; and (iv) there is a precisely known score for a memoryless policy, so "did it actually remember?" has a numerical answer rather than a qualitative one.

That last property is what makes the task useful as an interpretability substrate. A policy that ignores the hidden category still collects ⅔ of the reward (Section 2.5), so the gap between 67 % and 99 % is entirely attributable to a belief that was formed, retained across the corridor, and read out at the fork. Everything above the ceiling is memory.

2The environment

2.1Task structure

Each episode places the agent at the centre of the left edge of a 32×64 tile map. The map is drawn from one of three categories that differ only in the statistics of the terrain: lakes maps are water-heavy, rocky maps are rock-heavy, and balanced maps have both in equal measure. The category is never stated; it must be inferred from what the agent walks past.

An episode has four phases. The agent crosses open terrain where the category is visible; it then enters a 16-column corridor of pure grass that has been scrubbed of all category-carrying terrain; it passes through a 3-cell gap in a wall of trees; and it arrives in a narrow strip containing two single-cell doors, one at the top and one at the bottom. Reaching either door ends the episode; only the matching one pays the bonus.

2.2Observation and action space

The agent never sees the map. It receives a 21×21 egocentric crop of tile ids — symbolic, not pixels — one-hot over the 9 tile types, concatenated with 5 scalars: a one-hot heading (4) and elapsed time as a fraction of the step limit (1). Out-of-map cells carry a dedicated out-of-bounds id. The flattened observation is 21·21·9 + 5 = 3 974 floats. Panels (c–e) of Figure 2 show three real observations from one episode.

Actions are Discrete(6): four moves, plus build (turn the faced water tile into a wooden plank) and mine (turn the faced rock into grass). Both tools are optional — every obstacle can also be walked around — and agents use them only where cutting through is shorter. In the clips of Section 4.1 you can watch an agent lay a seven-plank bridge across a lake.

2.3Reward

The reward is dense and has three terms. A constant slack penalty per step creates time pressure; a potential-based shaping term pulls the agent along the shortest path to the correct door; and a bonus fires when the correct door is entered. The wrong door terminates the episode with no bonus — it is not punished, it simply ends the run.

rt = −0.01 + 0.015 · ( Φ(st−1) − Φ(st) ) + 3.0 · 1[ correct door ]
Φ(s) is the exact minimum number of actions from cell s to the rewarded door, computed by breadth-first search on the true map at reset. Because the shaping discount is 1.0, the shaping term telescopes: over a full episode it contributes exactly Φ(start) − Φ(end), so it cannot be farmed by looping, and it leaves the optimal policy unchanged (Ng et al., 1999). The bonus is paid only at the door that matches the map category; the decoy door pays nothing.
Two metrics, and why we report the stricter one Dense shaping means a fast wrong-door episode (~80 steps) collects more shaping than slack and ends with a positive return. So episode return > 0 and "reached the right door" are genuinely different questions, and they differ by 6–13 points depending on the agent.

Neither is wrong; they measure different things. By the reward's own logic a wrong door is a perfectly respectable outcome — it beats a timeout outright, since it banks the shaping, ends the episode early and stops paying slack. An agent optimising return is right to prefer a decisive wrong door over dithering. But this environment exists to measure memory, and only the door identity answers that question. Every number in this report therefore uses the door metric: success iff the final cell is in the map's rewarded-door set, with wrong-door and timeout reported separately so both readings stay visible.

2.4Dataset

All three agents train on one frozen dataset, forkwall6k: 6 000 procedurally generated maps, class-balanced across the three categories, split 4 800 train / 1 200 held-out by a fixed seed. Freezing the maps removes an otherwise invisible confound — with per-seed procedural generation, each agent would see a different map stream, and sample-efficiency comparisons would partly measure luck.

2.5The number to beat

Consider a policy that navigates perfectly but ignores the category — it always heads for, say, the top door. On rocky maps (⅓ of the data) it is correct. On balanced maps (⅓) either door is accepted, so it is correct. On lakes maps (⅓) it is wrong. Its expected success is exactly ⅔ ≈ 66.7 %.

This is the constant-door optimum, and it is a genuine attractor: it earns two-thirds of the reward for none of the memory. Every agent in this report gets stuck in it at some point during training (Section 8). Because balanced maps are free, the sharper statistic is decisive-door success — accuracy restricted to lakes and rocky maps, where a constant-door policy scores 50 %.

3How a Cogniland map is made

The generator is the part of this environment that decides what the agent has to remember. This chapter walks it end to end — first the noise that gives the terrain its shape, then the six stages that turn a field of floating-point numbers into a playable map, and finally the one line of code that separates a rocky map from a lakes map.

3.1Why not just place random tiles?

Sampling each cell independently — grass with probability p, water otherwise — produces static, not terrain. Every cell is uncorrelated with its neighbours, so you get salt-and-pepper noise with no lakes, no coastlines and no navigable structure. What a map needs is spatially correlated randomness: nearby cells should usually agree, distant cells should be independent, and the correlation length should be tunable. That is exactly what gradient noise provides.

3.2A primer on Perlin (gradient) noise

Ken Perlin's 1985 construction is the canonical way to get smooth, repeatable, band-limited randomness. The idea is short enough to state completely:

  1. Overlay an integer lattice on the plane. Assign every lattice point a fixed random unit gradient vector — not a value, a direction. The assignment is a deterministic hash of the coordinates, so the same point always gets the same vector, and the field is infinite and reproducible without storing anything.
  2. To evaluate the noise at a point p, find the cell containing it. For each of the 4 corners (8 in 3-D), take the offset vector from that corner to p and compute its dot product with the corner's gradient. This gives four scalars — each is "how far along this corner's preferred direction is the sample?"
  3. Blend the four values bilinearly, but warp the interpolation parameter through an ease curve first. Perlin's improved curve is 6t⁵ − 15t⁴ + 10t³, whose first and second derivatives vanish at t = 0 and t = 1. Linear blending would leave visible creases along cell boundaries; the quintic makes the field C²-continuous.

One noise field has a single characteristic feature size, which looks artificial. Real terrain has structure at every scale: continents, then bays, then boulders. The standard fix is fractal Brownian motion — sum several noise fields ("octaves"), each at half the wavelength and half the amplitude of the last:

h(x) = Σk=0..N−1   ak · noise( x / (λ · 2−k) )
Cogniland uses N = 5 octaves with amplitude ratio a = ½ and a base wavelength λ = max(H, W)/4.5 ≈ 14.2 cells, giving wavelengths of roughly 14.2, 7.1, 3.6, 1.8 and 0.9 cells with weights 1, ½, ¼, ⅛, 1⁄16. The sum is normalised by the total weight. The lowest octave decides where the continent-scale lakes go; the highest just roughens the coastline.
Perlin vs simplex — what the code actually calls Cogniland uses OpenSimplex (opensimplex.noise2array), not classical Perlin. Simplex noise, also by Perlin (2001), replaces the square lattice with a simplicial one (triangles in 2-D), which costs O(n²) instead of O(2ⁿ) corner evaluations per sample and — more importantly here — removes the axis-aligned directional bias that square-lattice Perlin leaves behind. OpenSimplex is a patent-free variant of that idea. Everything in §3.2 carries over unchanged: random gradients, dot products against offsets, smooth interpolation. The pictures above are generated with the same library the environment uses.

3.3Domain warping

Fractal noise alone still looks a bit like a topographic map of nowhere: the level sets are soft and rounded. Domain warping fixes this by distorting the coordinates before sampling — the field is evaluated not at (r, c) but at (r + α·wr(r,c), c + α·wc(r,c)), where wr and wc are two more (cheaper, 2-octave) noise fields. Cogniland uses α = 0.10 · max(H, W), so features can be dragged sideways by up to ~6 cells. Round blobs become bays and peninsulas.

3.4Stamping in the set pieces

Pure noise gives texture but not landmarks. On top of the warped heightmap the generator stamps a handful of explicit features, each a smooth scalar field added to (mountains) or subtracted from (lakes) the height, with weight ±1.3:

  • 2–4 lakes and 2–4 mountains, each 50/50 either a logistic disk (a flat-topped round basin) or a massif (3–5 overlapping Gaussian lobes, which reads as an irregular natural formation);
  • 0–1 ridge, a capsule field — a line segment with Gaussian falloff and a sinusoidal wiggle, giving a meandering mountain range or riverbed.

Feature radii are drawn as R = big · (lo + (hi−lo) · U²) with U ~ Uniform(0,1). Squaring the uniform biases the draw toward the small end, so most maps have several small features and only occasionally one dominating landmass — which is what keeps the map distribution varied rather than same-y.

3.5The line that creates the map types

Here is the mechanism the whole task rests on. The heightmap is a continuous field; turning it into tiles requires two cut points, and the generator picks them by quantile rather than by absolute value:

water_level = quantile(h, water_frac)          # lowest water_frac of cells become WATER
rock_level  = quantile(h, 1 - rock_frac)       # highest rock_frac of cells become ROCK

Because a quantile is defined by rank, this guarantees the requested coverage regardless of how that particular heightmap happened to come out. A map asked for 24.5 % water gets 24.5 % water, every time. The three map types are then nothing more than three pairs of fractions:

3.6The remaining stages

Four steps finish the map:

  1. Cosmetic fringes. A sparse one-cell speckle of SAND around water (30 % of the dilated ring) and DIRT around rock (25 %). Both behave exactly like grass — they exist so the eye reads a shoreline, and so a tile-identity probe cannot trivially equal a walkability probe.
  2. Edge bands. The leftmost and rightmost 10 columns are cleared to grass, guaranteeing the spawn is never walled in and — importantly — that the fork apparatus at the right edge never eats into the terrain that carries the category signal.
  3. Trees. Small impassable patches covering ~3 % of the map, biased toward the top and bottom walls so that hugging a wall is not a free route. Trees can be neither bridged nor mined; a reachability guard thins any patch that would seal off the goal.
  4. The fork apparatus. A TREE wall one column from the right edge with a 3-cell passage at mid-height; two single-cell doors on the right wall at rows H/4 and H − 1 − H/4; and the mem_gap = 16 columns immediately before the wall overwritten with pure grass — the memory corridor.

3.7Winnability

A map is only useful if it can actually be solved, so generation is rejection-sampled. After a candidate is built, a breadth-first search checks that the rewarded door is reachable under the crossing tool the map's type implies — water-crossing for lakes, rock-mining for rocky, either for balanced. If the check fails the seed is advanced by a prime offset (100 003) and the map is rebuilt, up to 400 times. The record keeps the requested seed, so a map is still reproducible from its id alone.

The consequence worth stating: every map in the dataset is winnable, and winnable in the way its type implies. A failure at evaluation time is never the environment's fault.

5The three agents

The agents span the two dominant families in modern model-based / model-free RL, and within the model-based family, the two dominant sequence backbones.

5.1PPO + GRU — model-free

A convolutional encoder over the one-hot minimap feeds a 128-unit GRU; actor and critic are linear heads on the recurrent state. Memory is whatever the GRU carries forward. An auxiliary head predicts the map category from the hidden state — it is a probe used to measure whether the belief exists, and in the released configuration it also shapes the representation (belief_coef 0.3). Trained with standard clipped PPO on 32 parallel environments.

5.2DreamerV3 — RSSM world model

An RSSM learns latent dynamics from a replay buffer: a deterministic GRU path of width 3 072 plus 32×24 discrete stochastic latents. The actor and critic are trained almost entirely inside imagined rollouts (horizon 15) rather than on real experience. Memory here is the recurrent latent state, and — crucially — the gradient that teaches the model to retain the category can only travel as far back as the training sequence is long.

5.3STORM — Transformer world model

Same imagination-based actor-critic, but the dynamics core is a 2-layer, 512-dimensional causal Transformer over (latent, action) tokens instead of a recurrent cell. During training the whole replay sequence is processed in parallel under a causal mask; at acting time a rolling window of the most recent tokens is re-encoded each step. The policy reads concat(zt, ht) — the current observation's latent plus the attention summary of the past.

Implementation note The STORM implementation we started from called its Transformer on one-token sequences and fed the actor only zt — a function of the current observation alone. That agent is memoryless by construction: it scored 100 % on a reactive control task and exactly 0 % here, across 6M frames. Restoring the original paper's scheme (parallel causal training, concat(z, h) features, history-conditioned reward and continuation heads, context-primed imagination) is what makes the STORM column of this report exist.

6Protocol

Cross-agent comparisons are only as good as the things held fixed, so we state them explicitly.

  • Environment and reward are byte-identical. Each pipeline wraps the same BridgeTunnelEnv class with the same keyword set; the wrappers differ only in how they batch and how they format observations for their trainer.
  • Data is identical. All agents draw training episodes from forkwall6k/train.pkl (4 800 maps) and are evaluated on forkwall6k/test.pkl (1 200 maps), which is never touched during training.
  • Evaluation is one harness. 900 episodes per agent, maps drawn with a shared seed, the TRUE door metric, outcomes bucketed into correct / wrong-door / timeout.
  • Each agent acts in its native mode. PPO and STORM sample from their policies; Dreamer acts deterministically. This is how each was trained and how each is intended to run — forcing a common mode would penalise agents for a mismatch that is not part of the method. (STORM in particular degrades badly under greedy action selection: it deadlocks against obstacles and times out on ~8 % of episodes.)

8What each agent needed

This is the part of the study that carries information. Reaching ~98 % was, in every case, gated on exactly one hyperparameter — a different one for each agent — and the default value of that hyperparameter produced a confident constant-door policy instead.

8.1PPO: an exploration problem

With default entropy, plain-reward PPO reliably collapses to the constant-door optimum. The diagnosis is unambiguous and slightly surprising: the belief is there and the policy ignores it. The auxiliary probe reads the category out of the GRU state at ~88 % accuracy while the actor still walks to the same door every episode. Going top already earns ⅔ of the reward, and on-policy PPO stops sampling the alternative long before it discovers that the other door is sometimes worth +3.

The fix is an exploration schedule, not a memory change: start at entropy 0.15 — high enough that both doors keep getting visited — and anneal to zero so the policy can sharpen once the contingency has been discovered.

8.2DreamerV3: a context-length problem

Dreamer's failure mode looked identical from the outside — a policy parked at ⅔ — but the cause is different. R2-Dreamer's replay sampler draws independent chunks and does not carry RSSM state across them, so the effective training context is exactly batch_length. At the default 64, the gradient from the door reward simply never reaches the timesteps where the category was visible ~75 steps earlier. The model cannot learn to retain what it is never asked to connect.

Doubling batch_length to 128 fixes it. In the 2×2 sweep over capacity and context, the only configuration that fails is the one with both the smaller model and the short window; every configuration with a long enough window clears the ceiling.

8.3STORM: a window problem, twice

STORM needed the same lever as Dreamer and then a second one that has no Dreamer analogue. The first is batch_length 64 → 128, for exactly the reason above: a causal Transformer attends only within its training window. The second is the acting-time context: at deployment STORM re-encodes a rolling window of recent tokens, and that window is a separate hyperparameter from the training window. With a 32-token window the agent was structurally blind to evidence 75 steps back even though its weights knew what to do with it — widening the window to 128 lifted held-out success by ~7 points with no retraining at all.

The third finding is about entropy, and it runs opposite to PPO. At entropy 0.03 STORM entrenched the constant-door habit (one category pinned at 0 % for the whole run); at 0.01 it bound both doors within the first 300 k frames. Model-based agents learn the contingency inside imagination, where the wrong door can be tried at no cost, so they need far less real exploration than PPO — and too much sampling noise actively prevents the policy from sharpening.

Metastability Door-binding in STORM is not a one-way transition. Across a run, held-out success oscillates between ~0.99 and dips as low as 0.72, recovering over 2–3 checkpoints; individual seeds differ in when (and whether) they bind. We therefore archive checkpoints every 50 k gradient steps and select on held-out data — the released checkpoint is the best of that archive, and reporting the final checkpoint instead would have understated the method by about a point.

9Limitations

  • Single seed per released agent. Table 3 compares one checkpoint per method. The seed-to-seed variance across the sweeps (Section 8) is larger than the between-agent differences, so the ranking in Table 3 should not be read as a ranking of methods.
  • Checkpoint selection differs. STORM's checkpoint was selected on held-out data from an archive; PPO's and Dreamer's are end-of-training. This favours STORM by roughly a point.
  • Action modes differ (Section 6). Defensible, but it means the comparison is "each method at its best" rather than a controlled ablation.
  • Compute is not matched. PPO reaches its result in 27 minutes; the world-model agents take 6–10 hours for comparable accuracy. On this task, the model-based machinery buys nothing in final performance — the interesting claim is only that it can be made to work at all on a memory task of this shape.
  • One task. Every conclusion here is about Cogniland.

10Reproducing this

Everything below runs from the repository root. The three pipelines use three separate environments and never import each other; they share only the environment package and the map dataset.

# 0 · the shared dataset (deterministic)
python scripts/bridge_tunnel/make_forkwall_dataset.py

# 1 · PPO + GRU                                       (conda env: crusoe)
python scripts/bridge_tunnel/train_ppo_bridge_tunnel.py \
    --config configs/bridge_tunnel/btc_ppo_forkwall_plain_solved.yaml \
    --maps-path data/bridge_tunnel/forkwall6k/train.pkl --total-timesteps 4000000

# 2 · DreamerV3                                       (conda env: r2dreamer)
BT_MAPS=$PWD/data/bridge_tunnel/forkwall6k/train.pkl \
python r2dreamer_model/train.py env=bridge_tunnel_forkwall \
    model=size25M model.rep_loss=dreamer batch_length=64 \
    model.act_entropy=0.01 env.train_ratio=64 env.steps=3e6

# 3 · STORM                                           (venv: STORM_model/.venv)
cd STORM_model && python -m scripts.train \
    --env-config   configs/envs/bridge_tunnel_storm2_run6.yaml \
    --agent-config configs/agents/sweep/stormH_ent001_bl128.yaml --offline

# 4 · the unified evaluation used for Table 3 (per agent)
python scripts/figures/paper_eval_all.py --agent {ppo|dreamer|storm} --episodes 900
